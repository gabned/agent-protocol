# Milestones, closure and handoff

After every significant milestone state briefly what is verified, one next action
and where it will happen, followed by remaining relevant milestones. If that action
belongs to the same already-authorized objective, announce it and continue in the
same session. Do not ask whether to continue or replace execution with a prompt.
Do not report after every command or confuse a plan with verified delivery.

At a real handoff or completed objective, give exactly one immediate action and
its operational location: here, a new conversation, Codex, ChatGPT/Work or an
indispensable human intervention. Include a short subsequent sequence only when
useful. A resume prompt is appropriate only for an actual context change and must
reference verified, accessible durable material rather than repeat unchanged logs,
audit text or code. Preserve the owner and required authorizations.

For a proposed new objective use a new conversation with the relevant prefix:
`Core e regole | ...`, `Rollout | ...` or `Diagnosi e recupero | ...`. Clearly
distinguish PREVISTI (planned steps), verified roadmap, new PROPOSTE and BLOCCHI.
Proposing work does not authorize it. Name a next version only when it is actually
defined; never invent a release or administrative micro-version to provide a sequel.

Choose model/effort only from options actually available in the execution host.
Retain that choice in the workstream checkpoint/handoff, not fixed model names in
permanent instructions. Report tokens, durations and AI/CI/laboratory costs only
when observed; otherwise UNKNOWN. Compare equivalent before/after scenarios and
separate text delivered to the model from raw bytes verified mechanically.

Closure must distinguish adoption, state migration, cleanup and native verification
per repository. Report unfinished checks and precise dependencies honestly. Preserve
durable work when blocked. Never promise asynchronous work without an actual
scheduled mechanism. Completion does not authorize PRODUCT or another release.
